## The problem (from Daniel, today)
When a managed session hits a LOGIN gate (a Claude Code session logged out,
`/login` flow, wrong account, OAuth URL + paste-code prompt), the manager has no
way to change the login or navigate that sequence — supervision dead-ends until
a human finds the pane. Today the fleet lost real time to exactly this.

## Build (scoped, ponytail rules apply — laziest thing that works)
1. **Detect**: teach the Tier-0 classifier (docs/emux-smart-classifiers.md,
   classifier code near tmux_classify) a `login_gate` signal — screen shows a
   login/auth sequence: "/login", "Select login method", "Paste code", "Press
   Enter to log in", claude.ai/oauth URLs, "Login successful", logged-out
   banners. State: waiting_human with flag `login_gate` (or a dedicated state if
   cleaner), so tmux_wait/classify surface it as "needs login", not generic.
2. **Navigate**: an `emux login <target>` CLI subcommand (+ MCP tool
   `tmux_login`) that drives the sequence on a registered session: send /login
   (or detect it's already mid-sequence), step through the TUI (reuse the
   existing navigate/goal machinery where possible rather than new keystroke
   logic), EXTRACT the OAuth URL from the pane and return/print it prominently
   (that's the human/browser hop — don't fake it), then accept a follow-up
   `emux login <target> --code <paste>` to finish, and verify success from the
   screen.
3. **Change login**: `emux login <target> --switch` = /logout first, then the
   sequence above.
4. Document in README + a short docs/ note. One runnable check per the repo's
   testing conventions (fraude-fleet skill exists for zero-token fake claudes —
   use it if it fits; do not drive a real claude login unless needed).
